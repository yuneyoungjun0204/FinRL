# 수익률 비례 확정 보상 체계 고도화

## 📋 개요

보상 함수를 **수익률 비례 확정 보상 체계**로 전면 개편하여, 에이전트가 단순히 매매를 끝내는 것이 아닌 **최대한 큰 수익률을 기록하도록** 유도합니다.

---

## 🔄 주요 변경 사항

### 1. 수익률 비례 확정 보상 (Scaled Realized Reward)

#### ✅ 미실현 보상 제거
- **변경 전**: 포지션 유지 중 자산 변화에 대한 실시간 보상 제공
- **변경 후**: 포지션 종료 시에만 보상 지급 (확정 수익만 반영)

#### ✅ 비례 보상 로직
```python
# _close_position() 메서드에서
pnl_pct = (realized_pnl / self.entry_size) * 100
reward = pnl_pct * 10.0  # 수익률이 높을수록 보상이 선형적으로 커짐
```

- **수익 시**: `+5% 수익 → +50.0 보상`
- **손실 시**: `-3% 손실 → -30.0 보상` (손실액이 커질수록 페널티도 선형적으로 증가)

#### ✅ 보유 시간 비용
```python
r_penalty -= self.time_penalty  # 매 스텝 -0.02
```
- **의도**: 효율적인 매매를 유도 (장기 보유 시 페널티 누적)

#### ✅ 파산 페널티
```python
if self.total_asset < 10.0:
    r_penalty += self.bankruptcy_penalty  # -50.0
```
- **의도**: 파산을 강력하게 억제

---

### 2. 관측값 및 제어 안정화

#### ✅ 입력 스케일 보정
```python
# _get_obs() 내에서
tech_scaled = self.tech_array[t] * 100.0
state_list.extend(tech_scaled.flatten().tolist())
```
- `tech_array`에 100을 곱하여 주입하여 입력 스케일 보정

#### ✅ 액션 페널티 상향
```python
self.action_penalty_coef = 0.5  # 기존 0.1 → 0.5
```
- 액션 분포를 0 주변으로 모아 안정화

---

### 3. 정책망 아키텍처 및 활성화 함수

#### ✅ 네트워크 구조
```python
policy_kwargs = dict(
    net_arch=dict(pi=[256, 128], vf=[256, 128]),
    activation_fn=th.nn.Tanh,
)
```

- **Policy Network**: 256 → 128 뉴런
- **Value Network**: 256 → 128 뉴런
- **Activation**: `Tanh` (음수 신호 유지 및 포화 억제)

#### ✅ PPO 파라미터
```python
PPO(
    learning_rate=0.0002,  # 수익률 비례 보상은 변동성이 크므로 학습률 낮춤
    ent_coef=0.1,
)
```

---

### 4. 로깅 및 시각화

#### ✅ 매매 종료 로깅
```python
print(f"  [거래 종료] {reason:8s} | 수익률: {pnl_pct:7.2f}% | 보상: {reward:8.2f}")
```

- 매매 종료 시 `pnl_pct`와 `reward` 값을 실시간 출력
- 거래 유형별로 구분하여 출력

#### ✅ 파산 로깅
```python
print(f"  [파산] 총 자산: ${self.total_asset:.2f} | 페널티: {self.bankruptcy_penalty}")
```

## 📊 보상 계산 흐름도

```
매 스텝 (step 메서드)
│
├─ 1. 액션 페널티 계산
│   └─ r_penalty = -0.5 * (action²)
│
├─ 2. 타임 페널티 계산
│   └─ r_penalty -= 0.02 (매 스텝)
│
├─ 3. 포지션 관리
│   │
│   ├─ [포지션 보유 중]
│   │   ├─ 미실현 손익 업데이트 (보상 반영 안 함)
│   │   ├─ Trailing Stop 체크
│   │   ├─ Stop Loss 체크
│   │   ├─ AI 판단 종료 체크
│   │   │
│   │   └─ [포지션 종료 발생 시]
│   │       └─ r_realized = pnl_pct * 10.0
│   │
│   └─ [포지션 없음]
│       └─ 보상 없음 (미실현 보상 제거)
│
├─ 4. 포지션 진입 체크
│   └─ [진입 조건 충족 시]
│       └─ r_penalty -= 0.1 (진입 페널티)
│
├─ 5. 파산 체크
│   └─ [total_asset < 10.0]
│       └─ r_penalty += -50.0 (파산 페널티)
│
└─ 6. 최종 보상 계산
    └─ final_reward = r_realized + r_penalty
```

---

## 🎯 설계 의도

### 1. **수익률 최대화 유도**
- 수익률에 비례하는 보상으로 **큰 수익을 기록하는 거래를 강화**
- 손실 시에도 선형적으로 페널티 증가하여 **손실을 빠르게 인지**

### 2. **효율성 강조**
- 매 스텝 타임 페널티로 **빠른 의사결정 유도**
- 미실현 보상 제거로 **실제 수익 실현에 집중**

### 3. **안정성 확보**
- 파산 페널티로 **리스크 관리 강화**
- 액션 페널티 상향으로 **과도한 레버리지 사용 방지**

### 4. **학습 안정화**
- Tanh 활성화 함수로 **포화 억제**
- 학습률 낮춤으로 **변동성이 큰 보상에 대응**

## 📈 보상 시나리오 예시

### 시나리오 1: 고수익 거래 종료
```
상황: LONG 포지션 진입 후 +10% 수익으로 종료 (보유 시간: 5 스텝)
- pnl_pct = +10.0%
- r_realized = +10.0 * 10.0 = +100.0
- r_penalty = -0.5 * (0.8²) * 5 - 0.02 * 5 - 0.1 = -1.7
- final_reward = +100.0 - 1.7 = +98.3
```

### 시나리오 2: 손실 거래 종료
```
상황: LONG 포지션 진입 후 -4% 손실로 종료 (보유 시간: 3 스텝)
- pnl_pct = -4.0%
- r_realized = -4.0 * 10.0 = -40.0
- r_penalty = -0.5 * (0.7²) * 3 - 0.02 * 3 - 0.1 = -0.945
- final_reward = -40.0 - 0.945 = -40.945
```

### 시나리오 3: 포지션 유지 중
```
상황: 포지션 보유 중 (미실현 손익 +2%)
- r_realized = 0.0 (미실현 보상 제거)
- r_penalty = -0.5 * (0.6²) - 0.02 = -0.2
- final_reward = 0.0 - 0.2 = -0.2
```

### 시나리오 4: 파산
```
상황: 총 자산이 $8.0으로 하락
- r_realized = 0.0
- r_penalty = -0.5 * (0.5²) - 0.02 - 50.0 = -50.27
- final_reward = 0.0 - 50.27 = -50.27
```

## ⚙️ 주요 파라미터

| 파라미터 | 값 | 설명 |
|---------|-----|------|
| 수익률 보상 계수 | 10.0 | `pnl_pct * 10.0` |
| `action_penalty_coef` | 0.5 | 액션 크기 페널티 계수 (상향) |
| `time_penalty` | 0.02 | 매 스텝 타임 페널티 |
| `bankruptcy_penalty` | -50.0 | 파산 페널티 |
| `entry_penalty_val` | 0.1 | 포지션 진입 페널티 |
| `learning_rate` | 0.0002 | 학습률 (안정화) |
| `ent_coef` | 0.1 | 엔트로피 계수 |
| Policy Network | [256, 128] | 히든 레이어 구조 |
| Value Network | [256, 128] | 히든 레이어 구조 |
| Activation | Tanh | 활성화 함수 |

## 📝 요약

보상 함수는 **4가지 핵심 원칙**을 따릅니다:

1. ✅ **수익률 비례 보상**: 포지션 종료 시 수익률에 비례하는 보상 (`pnl_pct * 10.0`)
2. ✅ **미실현 보상 제거**: 포지션 유지 중 보상 없음 (확정 수익만 반영)
3. ✅ **효율성 유도**: 매 스텝 타임 페널티로 빠른 의사결정
4. ✅ **안정성 확보**: 파산 페널티 및 액션 페널티 상향

이 설계는 **레버리지 거래에서 수익률을 최대화**하는 동시에 **리스크를 효과적으로 관리**하도록 유도합니다.
