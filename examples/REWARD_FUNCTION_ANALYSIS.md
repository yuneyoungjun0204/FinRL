# 보상 함수 설계 분석

## 📋 개요

`leverage_ex.py`의 `CryptoAnslEnv` 클래스에서 사용하는 보상 함수는 **3가지 구성 요소**로 이루어져 있습니다:

```python
final_reward = r_asset + r_bonus + r_penalty
```

---

## 🔍 보상 구성 요소 상세 분석

### 1. **자산 변화 보상 (r_asset)**

자산 변화에 따른 기본 보상입니다.

#### 1.1 포지션 종료 시 (명시적 종료)
```python
# _close_position() 메서드에서 반환
r_asset = realized_pnl * 2.0
```
- **계산 방식**: 실현 손익(PnL)에 **2배 가중치** 적용
- **의도**: 포지션 종료로 인한 실제 손익을 강조하여 학습

#### 1.2 포지션 유지 시 (연속 스텝)
```python
if r_asset == 0:  # 포지션이 종료되지 않은 경우
    r_asset = (self.total_asset - prev_asset) * 2.0
```
- **계산 방식**: 총 자산 변화량에 **2배 가중치** 적용
- **의도**: 미실현 손익 변화를 실시간으로 반영

**특징**:
- 양수: 자산 증가 → 양의 보상
- 음수: 자산 감소 → 음의 보상 (페널티)
- **2배 스케일링**: 손익의 중요성을 강조

---

### 2. **보너스 보상 (r_bonus)**

수익성 있는 포지션 종료 시 추가 보너스입니다.

```python
# _close_position() 메서드 내부
bonus = realized_pnl * 0.2 if realized_pnl > 0 else 0
r_bonus = bonus  # 포지션 종료 시에만 적용
```

- **계산 방식**: 실현 손익이 양수일 때만 **손익의 20%** 추가 보너스
- **의도**: 
  - 수익성 있는 거래를 더욱 강화
  - 손실 거래에는 보너스 없음 (0)

**예시**:
- 실현 손익이 +$10이면 → 보너스 +$2.0
- 실현 손익이 -$5이면 → 보너스 $0

---

### 3. **페널티 (r_penalty)**

액션의 불확실성과 과도한 진입을 억제하는 페널티입니다.

#### 3.1 액션 페널티 (매 스텝)
```python
r_penalty -= self.action_penalty_coef * (action_val ** 2)
# action_penalty_coef = 0.1
```

- **계산 방식**: 액션 값의 **제곱**에 0.1을 곱한 값만큼 차감
- **의도**: 
  - 액션의 크기(절댓값)가 클수록 페널티 증가
  - 확신 없는 액션(0에 가까운 값)을 장려
  - 과도한 레버리지 사용 방지

**예시**:
- `action = 0.0` → 페널티: -0.0
- `action = 0.5` → 페널티: -0.025
- `action = 1.0` → 페널티: -0.1
- `action = -1.0` → 페널티: -0.1

#### 3.2 진입 페널티 (포지션 진입 시)
```python
if abs(actions[0]) > 0.5 and self.positions[0] == 0:
    r_penalty -= self.entry_penalty_val  # entry_penalty_val = 0.1
```

- **계산 방식**: 포지션 진입 시 **-0.1** 고정 페널티
- **의도**: 
  - 무분별한 진입 방지
  - 신중한 진입 타이밍 학습 유도

---

## 📊 보상 함수 흐름도

```
매 스텝 (step 메서드)
│
├─ 1. 액션 페널티 계산
│   └─ r_penalty = -0.1 * (action²)
│
├─ 2. 포지션 상태 확인
│   │
│   ├─ [포지션 보유 중]
│   │   ├─ 미실현 손익 업데이트
│   │   ├─ Trailing Stop 체크
│   │   ├─ Stop Loss 체크
│   │   ├─ AI 판단 종료 체크
│   │   │
│   │   └─ [포지션 종료 발생 시]
│   │       ├─ r_asset = realized_pnl * 2.0
│   │       └─ r_bonus = realized_pnl * 0.2 (if pnl > 0)
│   │
│   └─ [포지션 없음]
│       └─ r_asset = (total_asset - prev_asset) * 2.0
│
├─ 3. 포지션 진입 체크
│   └─ [진입 조건 충족 시]
│       └─ r_penalty -= 0.1 (진입 페널티)
│
└─ 4. 최종 보상 계산
    └─ final_reward = r_asset + r_bonus + r_penalty
```

---

## 🎯 보상 함수 설계 의도

### 1. **수익성 강조**
- 자산 변화에 2배 가중치 적용
- 수익성 있는 거래 종료 시 20% 추가 보너스
- → **수익 실현을 적극적으로 장려**

### 2. **리스크 관리**
- Stop Loss (-4%) 자동 실행
- Trailing Stop (익절 메커니즘) 구현
- → **손실 제한 및 수익 보호**

### 3. **행동 제어**
- 액션 크기에 따른 페널티 (과도한 레버리지 방지)
- 진입 시 페널티 (무분별한 진입 방지)
- → **신중한 의사결정 유도**

### 4. **실시간 피드백**
- 포지션 유지 중에도 미실현 손익 변화를 보상에 반영
- → **연속적인 학습 신호 제공**

## 📈 보상 시나리오 예시

### 시나리오 1: 수익성 있는 거래 종료
```
상황: LONG 포지션 진입 후 +5% 수익으로 종료
- realized_pnl = +$5.0
- r_asset = +$5.0 * 2.0 = +$10.0
- r_bonus = +$5.0 * 0.2 = +$1.0
- r_penalty = -0.1 (진입 시) - 0.025 (액션 평균) = -0.125
- final_reward = +10.0 + 1.0 - 0.125 = +10.875
```

### 시나리오 2: 손실 거래 종료
```
상황: LONG 포지션 진입 후 -3% 손실로 종료
- realized_pnl = -$3.0
- r_asset = -$3.0 * 2.0 = -$6.0
- r_bonus = $0 (손실이므로 보너스 없음)
- r_penalty = -0.1 (진입 시) - 0.025 (액션 평균) = -0.125
- final_reward = -6.0 + 0.0 - 0.125 = -6.125
```

### 시나리오 3: 포지션 유지 중 (미실현 손익 변화)
```
상황: 포지션 보유 중, 자산이 +$1.0 증가
- r_asset = +$1.0 * 2.0 = +$2.0
- r_bonus = $0 (종료하지 않았으므로)
- r_penalty = -0.025 (액션 페널티만)
- final_reward = +2.0 + 0.0 - 0.025 = +1.975
```

## ⚙️ 주요 파라미터

| 파라미터 | 값 | 설명 |
|---------|-----|------|
| `action_penalty_coef` | 0.1 | 액션 크기 페널티 계수 |
| `entry_penalty_val` | 0.1 | 포지션 진입 페널티 |
| 자산 변화 가중치 | 2.0 | 자산 변화 보상 배율 |
| 보너스 비율 | 0.2 (20%) | 수익성 있는 거래 종료 시 보너스 비율 |
| `stop_loss_pct` | 0.04 (4%) | 손절 기준 |
| `ts_activation_pct` | 0.08 (8%) | Trailing Stop 활성화 기준 |
| `ts_callback_pct` | 0.0008 (0.08%) | Trailing Stop 콜백 기준 |

## 💡 개선 가능한 점

1. **시간 가중치**: 포지션 보유 시간에 따른 보상 조정
2. **변동성 조정**: 시장 변동성이 높을 때 페널티 증가
3. **연속 손실 페널티**: 연속 손실 시 추가 페널티
4. **샤프 비율 고려**: 리스크 대비 수익률을 고려한 보상

---

## 📝 요약

보상 함수는 **3가지 핵심 원칙**을 따릅니다:

1. ✅ **수익 실현 강조**: 자산 변화 2배 가중치 + 수익 시 20% 보너스
2. ✅ **리스크 관리**: Stop Loss, Trailing Stop 자동 실행
3. ✅ **행동 제어**: 액션 및 진입 페널티로 신중한 의사결정 유도

이 설계는 **레버리지 거래의 특성**을 고려하여 수익성과 안정성의 균형을 추구합니다.
